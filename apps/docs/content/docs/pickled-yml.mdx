---
title: pickled.yml reference
description: Every field the loader accepts, with the rules each one enforces.
---

A `pickled.yml` has four required top-level keys: `product`, `agents`, `access`, and `tasks`, plus optional `sources` and `threshold`. Each task is an `answer` task (deterministic text `checks`) or a `build` task (edit a workspace, run `verify`).

For editor autocomplete and inline validation, point your YAML tooling at the published [JSON Schema](https://pickled.dev/schema/pickled.schema.json). `pickled init` adds the directive for you:

```yaml
# yaml-language-server: $schema=https://pickled.dev/schema/pickled.schema.json
```

The schema validates structure (shapes, required fields, allowed values). The loader stays the source of truth for cross-references (a source / agent / access id that does not exist), reserved names, and provider-specific rules, and it gives the better error messages.

## `product`

```yaml
product:
  name: my-product
  description: short one-liner about what your product does
```

Both fields are required. They flow into the system prompt so the agent knows what it is being asked about.

## `sources`

A registered source is the public context Pickled may score against: a local file or a URL. Anything not registered does not count.

```yaml
sources:
  readme: ./README.md
  llms: ./llms.txt
  docs: https://example.com/llms-full.txt
```

A map of source id to a path or URL string. Local paths are read from disk; URLs are fetched at check time. The id `none` is reserved (it names the no-context path), so the loader rejects a source called `none`.

## `agents`

The agents that answer. Each needs a `provider` and a `model`.

```yaml
agents:
  quick:
    provider: claude-code
    model: claude-haiku-4-5
    maxTurns: 5
  api:
    provider: anthropic
    model: claude-haiku-4-5
    temperature: 0
    maxTokens: 4096
```

Providers: `claude-code` and `codex-cli` (CLI agents), `anthropic` and `openai` (API agents). Pin the model explicitly: aliases like `haiku` can resolve to different versions across SDK upgrades and break reproducibility. API agents accept `temperature` and `maxTokens`; CLI agents accept `maxTurns`. Mixing the two is rejected at load.

## `access`

A named context path: a `(source, tools)` pair, and the unit you compare across runs. The same source reached two ways is two different tests. A task forms one cell per `(agent × access)` pair, and each shows in the report as `agent · access`, so name paths to read well. The id `none` is reserved.

```yaml
access:
  memory: { source: none, tools: none } # no context, model memory only
  given_docs: { source: docs, tools: none } # docs injected into the prompt
  web_open: { source: none, tools: web } # web search, no hint
  web_docs: { source: docs, tools: web } # web search, docs URL as the target
  mcp_mintlify:
    source: none
    tools: mcp
    servers:
      mintlify:
        url: https://docs.example.com/mcp
        headers:
          AUTH_TOKEN: ${AUTH_TOKEN}
```

- `source` is a registered source id, or `none` for no context.
- `tools` is `none` (the source is injected into the prompt), `web` (the agent reaches it with web search), or `mcp` (the agent reaches it through the declared MCP servers).
- `servers` is required when `tools: mcp` and rejected otherwise. HTTP transports only. Name a server by its provider (`mintlify`, `context7`), not `docs`: the receipt records provenance as `mcp__<server>__...`, so you can tell which surface answered.

With `tools: none` the source is injected and the agent answers from it. With `tools: web` or `mcp` nothing is injected: the agent must reach the answer with its tools, and a cell that answers without invoking one is vetoed to `NO`, because model memory cannot testify to the path the cell is meant to test. With `source: none` the agent searches with no hint; with a URL source, that URL is handed over as the canonical target.

### Reading the comparison

Put several access paths on one task and the verdicts localize where the answer lives:

- `memory` fails, `given_docs` passes: your source carries the answer.
- `given_docs` fails: the answer is missing or unclear in that source. Fix the source.
- `given_docs` passes, `web_docs` fails: the source is good, but it is not discoverable on the open web.
- a `web` or `mcp` cell answers without calling a tool: vetoed to `NO`.

### Naming

The access name is the only place the report shows which path ran, so keep names boring and descriptive:

- **sources** are content nouns: `readme`, `llms`, `docs_bundle`.
- **access** names the path: `memory` (no context), `given_<source>` (source injected), `web_open` (web, no hint), `web_<source>` (web with that source as the target), `mcp_<provider>` (that MCP surface).
- **servers** are the provider or endpoint: `mintlify`, `context7`.

## `tasks`

A task is the unit of work: a `prompt` plus how success is proven. `kind` selects the proof and defaults to `answer`; set `kind: build` explicitly for build tasks (build is never inferred from shape).

### Answer tasks

```yaml
tasks:
  - id: install
    prompt: How do I install my-product?
    agents: [quick, api]
    access: [memory, given_docs, web_open]
    checks:
      mustMention: ["bunx my-product"]
      mustMentionOneOf:
        - label: names the entry point
          values: [quickstart, getting-started]
      mustNotMention: ["npm install my-product-cli"]
```

Each task forms one cell per `(agent × access)` pair. A task needs an `id`, a `prompt`, at least one `agent`, and at least one `access`. An answer task also needs at least one check.

### `checks`

- `mustMention` - every listed substring must appear in the answer.
- `mustMentionOneOf` - each group is satisfied when at least one of its `values` appears. A group is `{ label, values }`; the label names the group in the receipt.
- `mustNotMention` - none of the listed substrings may appear.

Each entry counts as one check. All matches are case-sensitive substrings. The cell score is the share of checks satisfied; the verdict is `YES` (all), `PARTIAL` (some), or `NO` (none).

### `examples`

Optional per-task sample answers (answer tasks only), scored offline by `pickled test` with no model calls.

```yaml
tasks:
  - id: install
    prompt: How do I install my-product?
    agents: [quick]
    access: [given_docs]
    checks:
      mustMention: ["bunx my-product"]
    examples:
      pass:
        - "Install it with `bunx my-product`."
      fail:
        - "Run `npm install my-product-cli`."
```

A `pass` example must satisfy every check; a `fail` example must miss at least one. A `pass` a check rejects means the check is too strict; a `fail` that satisfies everything means the check is too weak. Run with `pickled test .`.

### Build tasks

A `build` task proves success by editing a throwaway workspace and running verification, not by checking answer text. Build tasks run on edit-capable CLI agents only (`claude-code`, `codex-cli`).

```yaml
tasks:
  - id: toolbar
    kind: build
    prompt: Add a custom toolbar using my-product.
    agents: [builder]
    access: [given_docs]
    trials: 3
    workspace:
      path: ./fixtures/react-app
      setup:
        - bun install --frozen-lockfile
    verify:
      - bun test
```

- `kind: build` is required; build is never inferred from the presence of build fields.
- `workspace.path` is the fixture directory the agent edits, relative to `pickled.yml`. Optional `workspace.setup` runs before the agent (e.g. install).
- `verify` lists the commands that must pass after the agent stops. This is the build task's contract.
- `trials` is the number of independent runs per `(agent × access)` cell (default 1); the result is reported as `k/n`.

Build tasks forbid `checks` and `examples` (those score answer text); answer tasks forbid `workspace` / `verify` / `trials`.

## `threshold`

```yaml
threshold: 80
```

Optional. When set, the run passes or fails on the overall score. Omit it to see `Overall: X / 100` with no pass/fail verdict.

## Env-var expansion

String values matching `${UPPER_SNAKE_CASE}` are replaced with the corresponding `process.env` entry at load. Missing env vars become empty strings so the failure surfaces at the call site (e.g., a 401 from the MCP server) rather than at config load. Bun auto-loads `.env`.

## What pickled rejects at load

- A source or access path named `none` (reserved for the no-context path).
- An agent with an unknown provider, or one missing `provider` / `model`.
- `tools: mcp` without a `servers` map, or `servers` on a non-`mcp` access path.
- An answer task with no checks (`mustMention` / `mustMentionOneOf` / `mustNotMention` all empty).
- A task referencing an agent or access path that is not declared.
- A build task missing `workspace.path` or `verify`, declaring `checks` / `examples`, or assigned to a non-edit-capable (API) agent.
- Build-only fields (`workspace` / `verify` / `trials`) on a task without `kind: build`.
- The old `questions` top-level key, or a task's old `ask` field (renamed to `tasks` / `prompt`).
- API agents that set CLI-only fields, or a `codex-cli` agent without a pinned model.
