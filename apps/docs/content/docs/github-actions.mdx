description: Run pickled in CI with offline checks, a dry plan, and a capped agent run.

Use CI to keep the public context contract from drifting.

## Minimal workflow

```yaml
name: pickled

on:
  pull_request:
  push:
    branches: [main]

jobs:
  check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v6
      - uses: oven-sh/setup-bun@v2
      - run: bun install
      - run: bunx @pickled-dev/cli test .
      - run: bunx @pickled-dev/cli check . --plan
      - run: bunx @pickled-dev/cli check . --max-cells 20
        env:
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
          OPENAI_API_KEY: ${{ secrets.OPENAI_API_KEY }}
```

What each step does:

- `pickled test` scores example answers offline. It catches brittle checks before spending on a model run.
- `pickled check --plan` prints the cells that would run. No model calls.
- `pickled check --max-cells 20` refuses to run if the config expands beyond the cap.

Set a `threshold` in `pickled.yml` when you want CI to fail on a low score.

## Sample larger suites

For a broad suite, sample first:

```yaml
- run: bunx @pickled-dev/cli check . --sample 2 --seed pull-${{ github.event.pull_request.number || github.sha }}
  env:
    ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
    OPENAI_API_KEY: ${{ secrets.OPENAI_API_KEY }}
```

The seed makes the sample reproducible. The receipt records `expandedCells`, `selectedCells`, and `seed`.

## Secrets

- `ANTHROPIC_API_KEY` for Claude Code and Anthropic API agents.
- `OPENAI_API_KEY` for OpenAI API agents.
- MCP server secrets referenced in `pickled.yml` with `${UPPER_SNAKE_CASE}`.

Bun auto-loads `.env` locally. In Actions, pass secrets through the job `env`.
