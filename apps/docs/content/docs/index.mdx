Pickled is an open-source CLI that asks your product's real questions at real agents (Claude Code, Codex CLI, Anthropic API, OpenAI API), down named context paths (a source injected, or reached through `web` / `mcp` tools), then scores each answer with deterministic checks: must-mention, must-not-mention, any-of, and tool-use provenance. No LLM grades another LLM.

## What pickled tests

Two audiences, one tool:

- **External.** Vendors testing how outside-world agents understand their published product. Register your README, llms.txt, docs URLs, and the things you do not want agents to say. Pickled tells you whether the agent answered from your sources or made it up.
- **Internal.** Engineering teams testing whether their own CLAUDE.md, AGENTS.md, JSDoc, comments, and runbooks steer their own agents correctly. This repo is the dogfood case.

## How scoring works

A question runs once per `(agent × access)` pair. Each pair scores independently:

- **Checks.** `mustMention` and `mustNotMention` are substrings the answer must or must not contain; `anyOf` groups are satisfied when the answer contains at least one value from each. Each check counts once; the cell verdict is `YES` (all satisfied), `PARTIAL` (some), or `NO` (none).
- **Tool-use provenance.** When an access path uses `web` or `mcp` tools, the agent must invoke at least one of them, or the cell is vetoed to `NO`. Model memory does not count as evidence for a tool path.

## Getting started

Install the CLI, write a `pickled.yml`, run a check:

```bash
bunx @pickled-dev/cli init
bunx @pickled-dev/cli check .
```

See [Getting started](/getting-started) for a real first check.

## Why "pickled"?

Pickles are preserved. That is the point. Your product docs, examples, and agent instructions keep changing, but agents often carry old or partial versions of them. Pickled checks whether the important parts still hold up when an agent tries to use them.

The joke is small. The contract is serious.
