---
title: Access tools
description: Choose whether an agent gets injected context, web tools, or MCP tools.
---

An `access` path is a named `(source, tools)` pair. `tools` has three values today: `none`, `web`, and `mcp`.

## `tools: none`

```yaml
access:
  injected: { source: llms, tools: none }
```

Pickled reads the registered source and injects it into the prompt. Use this to ask: "is this source enough to answer the question?"

Use `source: none` with `tools: none` for a model-prior baseline:

```yaml
access:
  prior: { source: none, tools: none }
```

That cell gets no registered context and no tools.

## `tools: web`

```yaml
access:
  web: { source: none, tools: web }
```

The agent must use web search to reach the answer. Source content is not injected. A web cell that answers without invoking a web tool is vetoed to `NO`.

Works today on:

- Claude Code (`WebSearch` / `WebFetch`)
- Anthropic API (`web_search`)
- OpenAI API (`web_search`)

## `tools: mcp`

```yaml
access:
  docs_mcp:
    source: llms
    tools: mcp
    servers:
      docs:
        url: https://docs.example.com/mcp
        headers:
          AUTH_TOKEN: ${AUTH_TOKEN}
```

The agent must use one of the declared MCP servers. Source content is not injected. An MCP cell that answers without invoking an MCP tool is vetoed to `NO`.

Works today on:

- Claude Code through the Agent SDK MCP config
- OpenAI API through hosted MCP tools

OpenAI hosted MCP supports HTTP transports. `stdio` MCP servers are only usable through Claude Code.

## Secrets

`${UPPER_SNAKE_CASE}` values are expanded from `process.env` when the config loads. Bun auto-loads `.env` locally. In CI, pass secrets through the job environment.
